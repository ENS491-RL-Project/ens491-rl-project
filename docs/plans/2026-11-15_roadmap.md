## 1. The claim, made measurable (decision 0006)

| Part | Measurable form | Settled by | Refuted if | Today |
|---|---|---|---|---|
| A1 Compose (structure) | For a new task, a composite is built from the library and reaches STABLE without a human naming its children | W5 | Not STABLE in budget, or chosen children are meaningless | No evidence |
| A2 Compose (content) | The composite learns something the mask does not give it | W3, W5 | Same score and steps as random choice under the same mask | Order discovery only: under the strict mask random ties the learned composite; against goal-only random it is 4.4× (H-5) and 8× (H-6) fewer steps |
| B1 Reuse (transfer) | A frozen composite works untouched in a task it was not trained in, ≥ 0.90 | W2 | Each new task needs a near-copy | `unlock_door` → UnlockPickup 0.98 |
| B2 Reuse (fan-out, depth) | A composite has ≥ 2 distinct parents; T9b is cheaper than T9a | W2 | T9b ≥ T9a | One parent |
| B3 Reuse (cost) | Cumulative cost falls below flat; solves what flat cannot | W1b, W2, W4 | A flat learner with memory or fine-tuning does the same | Flat 0/50 after 3M on UnlockPickup; hierarchy unfinished there; as built through DoorKey 773,955 vs 650–900k |
| C1 No forgetting (system) | After each new task, all earlier tasks score the same end to end, recognition in the loop | W8 | Recognition degrades on old tasks | Not measured |
| C2 Price of not forgetting | Nodes added per task; share of near-copies | W2, W8 | Library grows faster than tasks | `open_door_tk` is the first copy |

Weak points to state in the report, not hide:
- Frozen skills cannot forget by construction. The claim is C1 plus its price C2, not "no forgetting".
- Phase B is structure selection for a task whose goal is given. Goal predicates and reset hooks are
  hand-written from privileged state; this is not skill discovery.
- Four tasks, one family, decomposed by the author. Growth is only really tested on a task the
  author did not decompose (W10).
- Novelty against CompoNet, HOP, CHiRP and Option-Critic can only be "a growing frozen library in
  which compositions are themselves children". Its evidence is B2 and W10; neither exists yet.
  (Literature positions are from `2026-10-04_literature_update.md`, read at abstract level.)

## 2. Workstreams

Criteria marked *(proposed)* are the advisor's and are not fixed until Emir fixes them in that
workstream's own plan, before its first run (decision 0010).

**W0 Evaluation ground** — done in part. PRs #15–#17 merged. Left: the final test seed set
(must avoid 50000–59999, used by W1). KB follow-ups are listed in `status.md`.
Owner: Pekpak. Emir decides: status of 0009.

**W1 Execution mode** — critical path. Open-questions rows 1–2; v2 §5.3–5.4; decision 0004.
- **W1a** (ready): does `pickup_box`, spec unchanged, pass when scored as it would act (sampled)?
  Existing trainer, fixed budget, final models scored once on 500 fresh seeds per row.
  Plan and criterion: `2026-11-15_W1a_pickup_box_sampled_plan.md`.
- **W1b** (after W1a): selectors sampled (B) or argmax (C); a stopping rule under sampling;
  `unlock_pickup`; flat UnlockPickup retrained with saved models. Needs trainer changes and decision
  file 0012 (0011 went to `pickup_box` specification 3), which must name 0004 and §5.3. Known requirements are listed at the end of the W1a plan.
- If W1a fails: a memory arm (frame-stacked or recurrent primitives) or an `epsilon` mode is the
  next plan. All 9 frozen nodes would need retraining for a memory arm.

**W2 UnlockPickup → Blocked (H-7, H-7b)** — after W1. Decision 0006 "missing (2)".
- Hypothesis: compositions work as children of later tasks (B1–B3).
- Experiment: T7; then T9a and T9b; a handoff row and a copy-node count for every node.
- Criterion *(proposed)*: T7 STABLE; T9b's own steps below T9a's.
- Known risk: frozen `get_key` picked up the ball in 29/50 in the Blocked pre-flight. Rebuild branch likely.

**W3 Choice task** — independent of W1 in content, but edits shared training files: schedule it
when W1 is not being edited. Open-questions "choice task"; Q8.
- Hypothesis: a selector can learn an observation-conditioned choice.
- Experiment: redesign so a wrong pick is unrecoverable; budget fixed in advance; 3+ seeds.
- Criterion *(proposed)*: first-key accuracy ≥ 0.90 on at least 2 of 3 seeds.
- If it fails, A2 is "order discovery"; the fallback evidence is W5's full-library selector.

**W4 Fair baselines** — open-questions "flat baseline memory"; 0006 "missing (4)".
- (a) Recurrent flat PPO on the curriculum tasks.
- (b) One flat PPO fine-tuned through the curriculum. Limit: it can show forgetting only on
  Unlock → DoorKey, because flat never learns tasks 3–4.
- Owner: a teammate. New scripts only; can run beside W1.

**W5 Growth, Phase B (G-1, G-2, G-3)** — after W1 (G-1 edits the same files). Decisions 0005, 0007.
- G-1: declare → train → evaluate → freeze → register as one API, on the run store.
- G-2 hypothesis: given a task (env + success signal) and the library, composite-first finds the
  children a human would declare.
- First experiment: replay Unlock and DoorKey. Two things to design before it: a parent's timeout
  may not be below a child's (`SkillNode` rejects it), so "all frozen nodes as children" needs a
  rule for candidates; and a random selector already solves 10–78% of DoorKey, so the control is
  random-under-the-same-mask, not zero.
- Open design gap: when a needed primitive is missing, who defines its goal?
  **G-2b** (advisor's idea): a composite over frozen children plus one trainable "residual"
  primitive that learns on the task's own reward from the states the frozen skills leave. This is
  a design project, not an extra arm: the trainer refuses a non-frozen child, and a primitive
  without a goal predicate has no reward or termination today. It touches the locked rule
  "children are FROZEN at creation" → `Proposed` decision file first. Fixed budget, one redesign at most.

**W6 Recognition (R-0, R-1, R-2, R-3)** — parallel; joins at R-3 (needs G-1) and G-3.
- State (PR #18): GRU with 9 classes, of which 7 are primitive skills and 2 are root tasks.
  v2 §6.2 has the GRU choose roots only.
- Two data issues: rollouts were collected with argmax policies (W1 may change how the agent acts)
  and on seeds 20000+, the skills' held-out set.
- **R-0** (new, cheap): with labels by root task, can the tasks be told apart from observation
  windows at all? Include UnlockPickup and Blocked (collectable with `unlock_door` or a random
  policy). Not established either way; grid size is not visible in a 7×7 view.
- R-2: old-task accuracy after each new task. R-3: task id → root, including which policy acts
  during the recognition window.
- Owner: Elif (GRU); AE (R-1) needs an owner. Must not become a precondition of W1, W2 or W5.

**W7 PN laterals (C-2)** — parallel; decision 0003.
- Hypothesis: a lateral from a frozen primitive reduces steps to STABLE for a new primitive.
- A 20% criterion is below what 3 seeds and `eval_every` 20,000 can resolve. Its plan must first
  fix seed count and evaluation spacing, then the criterion. A negative result is reported as such.

**W8 System-level continual evaluation** — after W2, W4(b), R-3. Evidence for C1 and C2.
After each new task: all earlier tasks on the final seeds with recognition in the loop; the
performance matrix; node count; W4(b)'s forgetting curve beside it.

**W9 GUI (UI-1, UI-2)** — parallel; reads the run store. Owner: a teammate.

**W10 A task the author did not decompose** — after W5. The real test of A1. Candidates
(KeyCorridor, ObstructedMaze) are not verified against the installed MiniGrid.
