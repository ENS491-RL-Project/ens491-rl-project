## Deviations and choices the plan did not spell out

Deviations from the plan: none in spec, hook, budget, thresholds, seed lists or criterion.

Added to the plan during the run, before any step-3 result was seen (13:46, scoring in progress,
output unread): if a handoff row has fewer than 475 valid episodes, the verdict is
"undeterminable (chain)". `eval_w1a.py` already withheld a verdict in that case; its wording is
"chain problem in seeds …; not judged" in the 43–47 file and "undeterminable (chain)" in the
extension file. They mean the same. The rule did not apply (491 valid).

Choices made while writing `eval_w1a.py` (before any score was seen), also recorded in each result
JSON under `implementation_choices`:
1. **Loading.** Run-store directories have no registry `meta.json`, so `NodeRegistry.load_into`
   cannot read them. The script builds the node from the spec, requires `run.json`'s `node_spec`
   to equal it, loads `policy_state_dict.pt`, and requires the weights to hash to the recorded
   `policy_sha256`.
2. **Load check.** Each model's argmax held-out score must equal its training run's, or the
   script stops.
3. **Own-hook harness:** `SubgoalEnv`, as training's held-out score. **Handoff harness:** plain
   env from UnlockPickup's reset, `chain(unlock_door, drop_held)`, as H-7a.5's condition H.
4. **Cross-check** against `evaluate_node` / `run_episode` in every row (stops on any difference).
5. **Validation gate** compares episode for episode (success and steps), stricter than the
   per-sampling-seed counts the plan asks for.
6. **Validity** is read once after the chain from the `StateView` (a door exists and is open,
   `carrying_type` is None). The script checks that it is the same in the argmax and sampled pass.
7. **Timeouts** are failures that used `pickup_box`'s full 120 steps. Failures cut short by the
   env's own 288-step limit are counted separately as `env_ended` (0 on every handoff row).
   On the own-hook row `SubgoalEnv` truncates at the node's own timeout, so `env_ended` equals
   `timeouts` there and does not mean the env limit (noted in the extension file).
8. **State repeats** are counted over argmax failures among valid episodes.
9. **Verdict** is computed by the script from the plan's rule; seed 42 is excluded.
10. **Extension output.** The 43–47 result file is never rewritten. `--extension` scores 48–52
    the same way into a separate file and computes the ten-seed verdict from both.

Other notes:
- Training runs and scoring ran in a separate git worktree. The run-store archives were copied to
  the main checkout's `runs/training/` and their `complete.json` hashes verified.
- The step-0 smoke and timing outputs were deleted; they count toward nothing.
