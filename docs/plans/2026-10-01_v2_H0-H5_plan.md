# Part A — v2 design critique and proposed amendments

Each row is a proposed edit to `docs/ENS491_Target_Architecture_v2.md`, to be applied in **H-0.5**.
**Approved** = decided in the review (F10, F11, F16, F20, F23 — all yes). **Baked in** = accepted as part
of the plan's approval. Nothing in Part A is open any more; the whole table is the H-0.5 work list.

## A.1 Execution semantics (§4) — the ones that would bite first

| # | §  | Problem | Amendment | Status |
|---|---|---|---|---|
| **F1** | 4.3 | **Masking rule change (your decision).** Availability currently reads `initiation(s) and not goal(s) and …`. With initiation masking on, T3 and T5 have exactly one legal child at every decision point — the composite policy learns nothing and C1 measures masking. | Availability becomes `not goal(s) and (is_primitive or any(child.available(s)))`. `initiation` stays on every node as task-representation metadata (the supervisor's "initial conditions") and is used by `SubgoalEnv` reset hooks and the Phase-3 planning hook, but **does not mask**. C1 gains two mandatory controls: a random-over-available-children baseline, and an initiation-masking-ON ablation. | Baked in |
| **F2** | 4.3/4.4 | **Re-selection livelock.** A primitive that TIMEOUTs has its goal still false, so it is immediately available again in an unchanged state — the parent can re-select it forever. Under F1 this is now live, not hypothetical. Each re-selection burns a full child timeout. | `max_decisions` becomes **mandatory**, not "a guard". Executor logs a re-selection counter per episode. Re-selection stays *legal* (it is the signal the parent must learn from), but the parent's own `timeout` and `max_decisions` bound it, and both are recorded in `meta.json`. | Baked in |
| **F3** | 5.2 | **All-False action mask crashes MaskablePPO.** sb3-contrib requires ≥1 valid action. Under F1 an all-False mask occurs whenever every child's goal already holds. | `OptionEnv` never presents an empty mask: if no child is available it ends the episode (`terminated` if `node.goal(s)` else `truncated`). `Executor` closes the frame with `TIMEOUT` before any policy call. Add an assertion that a mask reaching a policy has ≥1 True. | Baked in |
| **F4** | 3/4.3 | **`available()` is exponential on a DAG.** It recurses over children; a node reachable by several paths is re-evaluated once per path. Depth 5 / branching 5 ⇒ ~5⁵ predicate evaluations per decision, each touching env state. The depth-5 unit test in H-1 would be the first to feel it. | Availability is memoized per `(node, state_view.version)`. The Executor owns the cache and clears it each env step. | Baked in |
| **F5** | 4.2/4.4 | **Live mutable state.** `state` is `env.unwrapped`. Predicates, masks and the policy's obs must come from the same instant, and traces written for the GUI must be serializable, not references to a mutating object. | Introduce `StateView`: an immutable per-step snapshot (`carrying_type/color`, `agent_pos`, `agent_dir`, `doors[]`, `objects[]`, `step_count`, `env_terminated`, `version`). All predicates take a `StateView`. This also gives F4 its cache key for free, and gives UI-1 a serializable trace. | Baked in |
| **F6** | 4.4 | **`Executor.act` recurses** (`return self.act(obs, state)`) and restarts the termination scan from the top. Depth-bounded in practice, unbounded in the spec. | Rewrite as a bounded loop with an explicit iteration cap; exceeding it raises rather than hangs. A hung training run is far more expensive to diagnose than a raised exception. | Baked in |
| **F7** | 4.2 | **Goal true at reset** ⇒ the root terminates at step 0 with SUCCESS, silently inflating the success rate. | `SubgoalEnv.reset` and `OptionEnv.reset` assert `not node.goal(s₀)` and resample the seed if it holds. | Baked in |
| **F8** | 4.4 | `GAMMA` is a module-level global, and `observe_reward` increments `steps` for a frame pushed during the same step — the discount exponent for a fresh frame is ambiguous. | γ is a constructor parameter. Define: a frame pushed at env step *t* has `steps = 0` while acting at *t*, and `observe_reward` applies `γ**steps` **before** incrementing. | Baked in |
| **F9** | 4.3 | **Privileged-information asymmetry is undeclared.** Masks are computed from `env.unwrapped`; the policy sees only the 147-dim partial observation. Door state in particular is invisible unless the door is in view. | State it explicitly in §4.3: masking is privileged, policies are not. This is a legitimate design, but it is the reason the F1 masking ablation exists, and it must be in the report rather than discovered by a reader. | Baked in |

## A.2 Learning semantics (§5)

| # | § | Problem | Amendment | Status |
|---|---|---|---|---|
| **F10** | 5.1/5.2 | **Composites have no reward channel of their own.** §5.1 gives primitives `1 − 0.9·steps/timeout` on goal; §5.2 gives composites only the discounted base-env reward. Any composite whose goal is not the base env's success receives identically zero and cannot learn. It happens to work for T3 only because `door open` *is* Unlock's success condition. | **A node's reward is always defined by its own `goal` predicate, never by the env's reward** — same `1 − 0.9·steps/timeout` shape for primitive and composite. The base-env reward is not passed through. This also enforces the existing hard rule that parent SMDP reward and child subgoal reward stay on separate channels. | **Approved** |
| **F11** | 5.3 | **The stabilization rule is statistically soft.** At p=0.90, n=50 the SR estimate has σ≈0.042. "≥0.90 twice consecutively" with resampled eval seeds is selection-on-noise and stops on a lucky pair. | Fixed held-out eval seed set (50 seeds, same every eval). Criterion = SR ≥ 0.90 **and Wilson 95% lower bound ≥ 0.80** (R2 — the originally proposed 0.85 silently demanded 48/50), twice consecutively. At freeze time, one evaluation on a second seed set never used for stopping, reported in `meta.json`. Fallback if 50 episodes stay noisy: N=100 with LB ≥ 0.85. | **Approved, as corrected** |
| **F12** | 5.1 | Reward denominator is the **node's** timeout, so rewards are not comparable across nodes, nor to the flat-PPO baseline (which uses the env's `max_steps`). | Keep the shape as the training signal, but declare **success rate and episode length as the only reported metrics**. Reward curves are diagnostic only. | Baked in |
| **F13** | 5.1/5.2 | **No timeout-composition invariant.** Nothing stops the sum of child timeouts exceeding the env's `max_steps`, which makes the parent unable to succeed for reasons that look like a learning failure. Verified budgets are tight: Unlock 288, DoorKey-6x6 360. | Validate at node creation: `node.timeout ≥ max(child.timeout)` and, for a registered root, `timeout ≤ env.max_steps`. Record every timeout in `meta.json`. | Baked in |
| **F14** | 5.2 | γ^k is approximated by per-step γ (already marked 🧪), but `k` is only mentioned in `info`. If it is not logged from the first run, the exact-γ^k comparison needs a full re-run. | `info["k"]`, `info["child_outcome"]`, `info["child_id"]` logged on every decision from day one. | Baked in |
| **F15** | 5.2 | **Vectorization hazard.** `LateralMlpExtractor._acts` is one dict per module, overwritten on every `_extract`; `Column.forward` already runs `_extract` twice per call (action pass, then value pass) so the activations it returns are the value pass's. A frozen child shared across N `OptionEnv` copies is last-writer-wins. | Refactor `_extract` to **return** activations instead of storing them (small, local to `column_policy.py`; `get_activations()` kept for the GUI). Use `DummyVecEnv` only — `SubprocVecEnv` would need every frozen child loaded per subprocess. Add a test: `DummyVecEnv(n=4)` ≡ `n=1` for a scripted policy. | Baked in |
| **F16** | 5.1 | **Policy input is raw uint8.** Obs is `Box(0,255,(147,),uint8)` with values 0–10; SB3's `MlpPolicy` does not normalize a non-image Box, so raw integers enter the MLP. v2 fixes this for the AE but says nothing about the policy. | Add a `ChannelNormalize` wrapper (object/10, color/5, state/2) used by `SubgoalEnv`, `OptionEnv` and evaluation alike, default **on** for all new nodes. **Cost:** legacy `runs/pn4/col01` was trained on raw ints and becomes invalid as a C-2 lateral source unless retrained. Also changes the CLAUDE.md "hard rule" pipeline (dtype float32, still 147 dims). | **Approved** (on; C-2 source retrained) |
| **F17** | 5.4 | Deterministic frozen policies loop under partial observability (v2 acknowledges this). Under F1 each loop costs the parent a full child timeout. | `Executor` takes `execution_mode ∈ {deterministic, stochastic, epsilon}` from construction, default `deterministic`. Log per-child timeout/loop rate so the 🧪 comparison is free. | Baked in |

## A.3 Node model, graph, recognition, PN, growth (§2, §3, §6, §7, §8)

| # | § | Problem | Amendment | Status |
|---|---|---|---|---|
| **F18** | 2 | **No node identity.** Frozen nodes are reused across experiments, but nothing ties a checkpoint to the predicate/timeout/env spec it was trained under. They are not reproducible from their own metadata. | Every node writes a `spec_hash` over (env id, goal/initiation source, timeout, children's spec hashes, obs pipeline, normalization flag). `NodeRegistry.load` refuses a mismatch. | Baked in |

# Risks accepted, and what would change the plan

| Risk | Signal it is happening | Response |
|---|---|---|
| Primitives don't transfer into parent layouts (F29) | T1/T2 succeed from hook states but fail from parent-reachable states in H-4's gate | Widen the layout and start-pose mix; if that fails, train primitives directly inside the parent env with the parent's reset distribution |

| CPU throughput too low for the SMDP | steps/s measured in H-4 implies H-6 runs over days | Reduce `max_decisions` and timeouts, use `DummyVecEnv(n=8)`, or move the long runs to the M5 Pro machine |

| `OptionEnv` cannot be vectorized because frozen children hold per-env state (F15) | `DummyVecEnv(n=4)` ≢ `n=1` test fails | **Stop and report** — CLAUDE.md lists this explicitly as a stop-and-report condition |
